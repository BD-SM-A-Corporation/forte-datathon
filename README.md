# Forte — интерфейс локального видеоанализа

Требуется Node.js 20.9+ и установленный npm/bun. Из каталога `front`:

```bash
cp .env.example .env.local
# Заполните BACKEND_API_KEY тем же значением, что API_KEY в backend/.env
# BACKEND_API_URL — адрес FastAPI, доступный серверу Next.js
bun install
bun dev
```

Интерфейс: http://localhost:3000. Сервер и worker запускаются по инструкции в `../backend/README.md`.
Для production: `bun run build`, затем `bun start`.

Браузер отправляет MOV в `/api/backend/analyze`. Next.js передаёт файл потоком
на FastAPI и добавляет серверный `X-API-Key`. Ключ не попадает в клиентский bundle.
Прокси интерфейса публичен: при публикации ограничьте доступ к UI/прокси средствами
внутреннего контура или reverse proxy, если этого требует окружение.
Жюри получает непосредственно адрес FastAPI `/api/v1` и отдельный ключ доступа.
Настройте reverse proxy на приём файлов до 512 МБ и достаточное время загрузки.
Не размещайте видео-прокси на платформе с меньшим лимитом тела запроса.

UI опрашивает статус последовательно каждые 1,5 секунды, обрабатывает `done` и
`failed`, ограничивает ожидание пятью минутами и никогда не заменяет ошибку
демонстрационным результатом. Все 1–3 JPEG каждого события доступны в галерее.
Нормативные ссылки и уверенность берутся из дополнительного `/jobs/{id}/details`;
при отсутствии этих данных UI сообщает об отсутствии основания.
JSON скачивается в формате ТЗ. Исходное видео доступно в плеере только в текущей
сессии загрузки: API не предоставляет URL для воспроизведения исходника.
Браузерная поддержка кодека MOV зависит от браузера; JPEG-доказательства доступны независимо.

**Реестр `backend/rules/regulations.json` пока пуст.** Бекенд возвращает ошибку,
пока проверенные правила не настроены. Для реального анализа также нужны Redis,
запущенный worker и локальные веса Qwen2.5-VL. Интернет для обработки не нужен;
интерфейс использует системные шрифты без загрузки Google Fonts.
